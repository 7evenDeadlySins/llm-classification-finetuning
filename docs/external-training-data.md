# Candidate External Training Data (Human Preference and Tie Semantics)

[Documentation index](../README.md)

This reference catalogs publicly available **real human preference datasets** with explicit tie choices or aggregate preference scores (and, where noted, **multi-turn conversations**) for the [Kaggle LLM Classification Finetuning](https://www.kaggle.com/competitions/llm-classification-finetuning) task. Aggregate zero scores need a separate interpretation; candidate inclusion does not establish matching label semantics or a validation benefit. See the [2026-11-17 source audit](data-source-audit-2026-11-17.md).

The historical LMSYS baseline merged `lmsys/chatbot_arena_conversations` (33,000 raw rows; 20,050 rows retained under its older prompt deduplication) with the 57,477-row Kaggle data, and used a separate 1,012-row build supplement. Current presets consume the larger real-data merge and scope-specific supplements described in [data preparation](data-preparation.md#merged-external-preferences). The audit compares that historical training table with the current mixture.

## Related single-turn datasets with native ties

These datasets also provide real human votes with ties, though they are single-turn only:

* **[`allenai/multipref`](https://huggingface.co/datasets/allenai/multipref)** (`10,461` rows, `odc-by` license): Single-turn prompts annotated by 2 crowdworkers and 2 domain experts on a 5-point Likert scale including `Tie`. Roughly 1,100 prompts originate from `lmsys/chatbot_arena_conversations` and must be deduplicated.
* **[`lmarena-ai/PPE-Human-Preference-V1`](https://huggingface.co/datasets/lmarena-ai/PPE-Human-Preference-V1)** (`16,038` rows, single-turn, 121 languages, 20 models): 4-class `winner` (`model_a`, `model_b`, `tie`, `tie (bothbad)`). The dataset card explicitly states *"meant for benchmarking and evaluation, not for training"*, and samples overlap with 2024 Arena data.

## Integration checklist for this codebase

Before adding any of the datasets above to a new processed dataset under `data/processed/`, preserve the invariants in [data-preparation.md](data-preparation.md) and [inputs.py](../src/llm_classification_finetuning/models/common/inputs.py):

1. **Frozen validation isolation and battle deduplication:** Keep the 11,495 Kaggle IDs in [validation_ids.csv](../data/processed/lmsys33k/validation_ids.csv) fixed. Compute `group_id` (SHA-256 of canonical prompt JSON) for every external row and exclude external rows sharing a prompt with the frozen **validation partition**. Deduplicate the remaining external rows internally, across external datasets, and against the existing Kaggle **training partition** and LMSYS training rows by complete prompt context and response pair, including A/B-swapped duplicates. Retain every distinct response pair for the same prompt, including external rows sharing a prompt with Kaggle training rows. Append retained rows exclusively to `split="train"`; `group_id` alone is not a training-sample deduplication key.
2. **Schema & turn validation:** Convert `conversation_a`/`conversation_b` (or `context` + `response1`/`response2`) into JSON arrays of alternating `user`/`assistant` turns, ensuring `prompts[0] == prompts[1]`, `is_swapped=False`, and mapping `tie` + `both_bad`/`tie (bothbad)` to `label=2`.
3. **Session context & length filtering:** Follow the [adopted processing principle](recommended-external-data.md#已确定的处理原则): retain each valid vote with its complete context. For `140k` and `arena-expert-5k`, restore earlier evaluation history from `full_conversation`; do not discard votes solely because `evaluation_order > 1` or because they share session history. Deduplicate actual battles by complete context and response pair, including A/B-swapped duplicates; retain all distinct response pairs for the same training prompt, while validation prompt groups stay isolated. Check complete unpadded branch lengths with the pinned `Skywork/Skywork-Reward-V2-Qwen3-4B` tokenizer against the 40,960-token model context (no truncation is allowed).
4. **Tie ratio & domain shift:** Measure the resulting `tie` fraction after merging, and benchmark both direct mixing and two-stage sequential fine-tuning (external warmup/pre-finetune followed by Kaggle + LMSYS33K fine-tuning) on the frozen 11,495-row validation set.
